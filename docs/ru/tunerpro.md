# Описания для TunerPro

`xdf/<номер>.xdf` — описание для TunerPro для каждого из одиннадцати образов, сгенерированное из
разметки инструментом `tools/xdf.py`. Откройте в TunerPro нужный `.bin` и выберите XDF с тем же
номером: адреса в семействах разные, а подписи рядов считаются по конкретному образу.

**Состояние: сгенерировано, в TunerPro ещё не проверялось.** Файлы — корректный XML (это проверяет
CI) и следуют раскладке XDF 1.60, которой пользуются другие генераторы, но раскладка 2D-таблиц
(чередующиеся пары x/y, чтение с шагом 16 бит) и нумерация категорий в самой программе ещё не
проверены. Пожалуйста, сообщите, что не открывается или показывает неверные значения.

## Что внутри

| Категория | Содержимое |
|---|---|
| Fuel | основные и WOT топливные таблицы (в % изменения длительности по MAP), масштабы MAP, мёртвое время, поправки по барометру и температуре воздуха, ускорительное, послепусковое и пусковое обогащение, отсечка |
| Spark | основной и WOT УОЗ (градусы), поправки, накопление катушки |
| Knock | управление по детонации |
| Idle | управление ХХ, включая `IdleTargetRpm` |
| Closed loop | обратная связь по кислородным датчикам |
| Sensors | кривые термисторов, замена ДПДЗ при отказе, обработка датчиков |
| Diagnostics | монитор пропусков зажигания и другие мониторы OBD |
| Speed control | круиз-контроль (вероятно) |
| Cooling fan | вентилятор радиатора, реле и ШИМ |
| EGR | управление EGR (вероятно) |
| A/C | муфта кондиционера (вероятно) |
| EVAP purge | продувка адсорбера и учёт паров (вероятно) |
| Startup | значения, задаваемые при сбросе |
| Options | байты настроек $0328-$0340, флаг на каждый используемый бит |
| Faults | `FaultTable`: строка на неисправность, P-код в подписи строки |
| Other | таблицы ещё не определённых подсистем |

В эталоне у каждой таблицы есть имя, данное вручную по коду (см.
[calibration.md](calibration.md)); в описании каждой сказано, какая подпрограмма её читает, какие у
неё входы и куда идёт результат. Другие образы получают те имена, которые смог перенести перенос (от
131 таблицы в семействе A до 403 в семействе E); остальные сохраняют сгенерированное имя `Tab...`.
Единицы берутся из разметки или из входов там, где они известны (об/мин, °C, кПа, вольты).

В XDF есть и 1451 константа эталона (пороги, ограничения, времена,
коэффициенты), как XDFCONSTANT с единицей там, где она известна, и каждый используемый бит байтов
настроек как XDFFLAG (см. [calibration.md](calibration.md)); другие образы получают константы,
которые перенёс перенос (от 239 в семействе A до 1404 в семействе E).

`tools/xdfcheck.py` сверяет сгенерированный XDF с образом: каждый элемент должен лежать внутри
таблицы или константы с тем же именем, размеры таблиц должны совпадать с их заголовками, маски флагов
должны быть битами, которые проверяет код, никакие два элемента не должны делить байты, а формулы
единиц должны давать правдоподобные значения (обороты, °C, кПа, вольты, градусы) для значений в
образе. Ей нужны файлы образов, которых нет в репозитории, поэтому она запускается локально; на
всех одиннадцати XDF ошибок нет. Остались только предупреждения о трёх
безымянных 2D-таблицах в перенесённых образах, у которых значения x идут не по порядку
(`Tab2D_04FB` в семействе A, `Tab2D_050D`, `Tab2D_2C31`), — возможно, это не настоящие таблицы.

`tools/edittest.py` (запускается в CI, образ не нужен) правит копию исходника: ячейку
`PartThrottleFuelMain`, константу `RevLimit` и бит 5 `Options0337`. Затем пересобирает, проверяет,
что изменились ровно эти три байта и что именно на них указывает XDF, запускает
`tools/fixsum.py --fix` и проверяет, что добавился только байт коррекции по $0030F, а сумма верна.

Списки условий мониторов OBD (см. calibration.md) есть в XDF как небольшие таблицы в разделе
Diagnostics, с именем переменной ОЗУ и проверки в каждой строке.

## Оси

- 3D-таблицы с записанной осью столбцов: ось читается из образа и редактируется (обычно обороты).
- Ряды 3D-таблиц не записаны: ряд выбирается таблицей масштаба MAP (`PartThrottleMapScale`,
  `WotMapScale`). XDF подписывает каждый ряд значением MAP, которое его выбирает, посчитанным по
  таблице масштаба **в момент генерации**. Если изменить таблицу масштаба, подписи рядов останутся
  старыми, пока XDF не сгенерировать заново (`python3 tools/xdf.py roms/<номер>.bin xdf/<номер>.xdf`).
- У 3D-таблиц без записанной оси показаны позиции 0-255.
- 2D-таблицы: значения x — редактируемая ось, значения y — столбец данных.

## Единицы

Как в [calibration.md](calibration.md): об/мин = x * 32, кПа = x / 2,428, УОЗ = x / 2 градуса,
°C = x - 128, вольты = x / 16,19 (бортсеть) или x / 51 (детонация), мёртвое время в микросекундах =
x * 32. Топливные таблицы показаны как процент изменения, (x / 256) * 100, со знаком.

## Контрольная сумма

TunerPro не исправляет контрольную сумму SBEC3. После сохранения изменённого образа запустите

```sh
python3 tools/fixsum.py edited.bin --fix
```

Он ставит байт коррекции (заголовок + 13) так, чтобы 8-битная сумма образа снова равнялась последнему
байту номера детали. Без `--fix` только проверяет.
