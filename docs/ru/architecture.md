# Архитектура программы

Здесь описан каркас программы эталонного образа **05293190AC**: запуск, память, прерывания и два
планировщика. Имена относятся к сгенерированному исходнику в `src/05293190AC/` и к `annotations/`.
У каждой подпрограммы этого образа есть имя (`annotations/labels.json`, 630 имён). Где назначение
не вполне ясно, имя нейтральное (`OutputTestB`, `MonTaskC`, `PciStateSet3`). В других семействах
номера вида `Sub_2CC42` остаются там, где подпрограмма ещё не сопоставлена с эталоном. У других семейств та же структура по
другим адресам (этап 5).

## Настройка железа (код сброса)

`Reset` ($0D08C) настраивает контроллер до запуска всего остального:

| Что | Значение | Итог |
|---|---|---|
| Стек, Z, регистры расширения | SK = ZK = $F, SP = $8FFE, IZ = $8000, EK = 0 | Z = $F8000 (начало ОЗУ); расширенные адреса читают банк 0 (калибровку) |
| Тактовая частота | SYNCR = $7F80 | 16,78 МГц от опорных 32,768 кГц |
| Внутреннее ОЗУ | RAMBAH/RAMBAL = $FF8000 | 4 КБ по адресам $F8000-$F8FFF |
| Периодическое прерывание | PITR = 7, PICR = $0338 | каждые 7 x 4 / 32768 с = 0,854 мс, уровень 3, вектор $38 |
| Программный сторож | SYPCR = $94 | обслуживается в `KickWatchdogs` |
| Выборки кристалла | CSBOOT, CS0: база 0, 256 КБ; CS2: база $F9000, 2 КБ | флеш; одно внешнее устройство по адресам $F9000-$F97FF |
| GPT | ICR = $B340 | уровень 3, векторы $40-$4B; вход счётчика импульсов назначен «выделенным» каналом |
| SCI / QSPI | QILR = $1B, QIVR = $FE | вектор SCI $FE, вектор QSPI $FF |

К внешнему устройству на CS2 обращаются как `$1000,Z`-`$17FF,Z`; код использует там 61 разный адрес.
Это микросхема таймеров, драйверов выходов и интерфейса шины, она описана ниже.

Сброс также считает причины перезапуска: биты регистра состояния сброса RSR модуля SIM добавляются
4-битными счётчиками в `ResetCountsExtSw` ($08,Z: внешний сброс, программный сторож) и
`ResetCountsHltPow` ($09,Z: монитор останова, включение питания). `ResetCheckWord` ($06,Z)
перезаписывается на каждом проходе главного цикла и проверяется при сбросе, чтобы отличить тёплый
перезапуск от холодного старта.

## Карта памяти

| Адрес | Содержимое | Обращение |
|---|---|---|
| $00000-$001FF | векторы исключений | |
| $00200-$0FFFF | заголовок, калибровка, затем код | `$xxxx` (EXT, EK = 0) для калибровки |
| $10000-$3FFFF | код и таблицы | `JSR $xxxxx`, индексно с XK/YK |
| $F8000-$F8FFF | ОЗУ (4 КБ) | `$xxxx,Z` |
| $F9000-$F97FF | внешнее устройство (CS2) | `$1xxx,Z` |
| $FF700-$FFDFF | регистры модулей (ADC, MRM, GPT, SIM, SRAM, QSM) | `$7xxx,Z`, имена в `00_equates.asm` |

Отдельные биты флаговых байтов ОЗУ описаны в `annotations/bits.json`. Генератор пишет смысл бита
после каждой команды `BSET`/`BCLR`/`BRSET`/`BRCLR` с этим битом и под байтом в `00_equates.asm`.
Биты `FaultSet00-1B` и `FaultMem00-1B` берутся из самой таблицы неисправностей: в каждой строке
указаны байт, бит и P-код.

Биты конфигурации калибровки лежат около $0328-$0338 и проверяются командами `BRSET`/`BRCLR` по
расширенным адресам, например `BRSET $032E,#$04,...` (см. ниже). Смысл каждого используемого бита
тоже записан в `annotations/bits.json`; его показывают исходник и флаги XDF.

## Устройство CS2 ($F9000)

Выборки кристалла SIM настраиваются в коде сброса: CSBOOT и CS0 охватывают 256 КБ флеш-памяти
программы (CSBOOT читает, CS0 только пишет — для программирования), CS1 и CS3-CS10 выключены, а CS2
открывает окно 2 КБ по адресу $F9000: 16-битные данные, чтение и запись, один такт ожидания. Программа
обращается к нему как `$1xxx,Z`. Это периферийная микросхема, а не память: используются только
смещения $000-$084, и по тому, что код с ними делает, это совмещённые таймер, драйвер выходов и
интерфейс шины. Имена регистров в `ram.json` начинаются с `Io`, их биты — в `bits.json`.

| Смещение | Имя | Назначение |
|---|---|---|
| $000-$001 | `IoInputs0`, `IoInputs1` | дискретные входы: ключ выключен (бит 3, вероятно), есть питание от реле ASD (бит 2, вероятно), выключатель насоса LDP, выключатель круиз-контроля; из этого слова собирается карта выключателей; биты обратной связи некоторых драйверов |
| $002-$003 | `IoStatus2`, `IoStatus3` | биты состояния драйверов и детонации |
| $006-$010 | `IoTimer06` ... `IoIrqStatus` | таймеры и регистры прерываний: `IoIrqEnable` ($00C) и `IoIrqStatus` ($00E, сбрасывается записью единиц) |
| $016, $01A | `IoBusData`, `IoBusStatus` | принятый байт шины и его биты ошибок ($000E), их читают обработчики шины по IRQ4 и IRQ2 |
| $012-$020 | `IoCtl12`, `IoCfg14` ... `IoCfg20` | слова управления и настройки, записываются при сбросе и проверяются в `HardwareCheck` |
| $024-$038 | `IoOcChan0-5` | шесть выходных каналов, их задаёт `OcOutputsReset` и запускает тест выходов |
| $03E-$050 | `IoPwmC18A/B`, `IoFanPwmA/B`, `IoPurgePwmA/B` | пары период/скважность ШИМ (выход C18, вентилятор, продувка) |
| $056-$060 | `IoInjector0-5` | шесть таймеров форсунок, пишут `FuelEventCalc` и `InjectorSequence` |
| $062-$06E | `IoDriver62` ... `IoDriver6E` | по слову на каждый ключ нижнего плеча: бит 13 — выход включён, биты 15-14 — состояние драйвера (клапан LDP, лампа/C18, клапан настройки впуска, вентилятор, продувка, обмотка возбуждения генератора) |
| $070-$07A | `IoEvent70` ... `IoEvent7A` | шесть слов, которые очищает `EventCorrections` |
| $07E-$084 | `IoPwmC18Read`, `IoFanPwmRead`, `IoKnockRead` | обратное чтение выходов ШИМ и настройки детонации |

IRQ2 приходит от этой микросхемы. `Isr_IRQ2` читает `IoIrqStatus`: событие шины (бит 3 младшего
байта) уходит в `Irq2Dispatch` и обработчик CCD/PCI, событие таймера (бит 1 старшего байта)
считается в `Irq2Counter` для времён сегментов монитора пропусков, всё прочее сбрасывает все флаги.
IRQ4 запускает `Irq4BusHandler`: он читает принятый байт и его состояние из `IoBusData`/`IoBusStatus`
и сравнивает с только что отправленным байтом (арбитраж шины). Значит, интерфейс CCD (или PCI) тоже
входит в эту микросхему.

## Прерывания

| Вектор | Обработчик | Назначение |
|---|---|---|
| $38 | `Isr_PIT` ($08344) | время 0,854 мс, быстрый планировщик (ниже) |
| $40 | `Isr_GPT_PAI` ($0AAEA) | вход счётчика импульсов: сигнал распредвала; первый фронт ставит `CrankSyncFlags` = $84 (синхронизация) и бит 2 `DriveFlags` |
| $41 | `Isr_GPT_IC1` ($0A02E) | захват 1: опорный сигнал коленвала (`RefPeriod`, `EngineRpm`, события топлива и зажигания) |
| $42 | `Isr_GPT_IC2` ($0ACD2) | захват 2: запускает измерение периода и разрешает IC1; IC1 отбрасывает импульс короче $10 отсчётов после TIC2, так что IC2, вероятно, видит другой фронт сигнала коленвала |
| $43 | `Isr_GPT_IC3` ($080CA) | захват 3: импульсы датчика скорости (`DistancePulses`) |
| $45, $46, $47 | `Isr_GPT_OC2/3/4` | три канала катушек зажигания (`SparkOutputOc2`; биты состояния драйверов 1-3 в `IoCfg1FL`); форсунки работают от таймеров микросхемы CS2 |
| $48 | `Isr_GPT_IC4OC5` ($08A90) | захват 4: второй вход отсчёта для зажигания по событиям, только с битом калибровки $0337.7; использует таблицу по $08A6C |
| $49 | `Isr_GPT_Overflow` ($0ACF0) | считает переполнения таймера в `Ic2OverflowCount` (с насыщением) |
| $12 | `Isr_IRQ2` ($089BE) | внешнее прерывание от устройства на CS2 |
| $14 | `Isr_IRQ4` ($08A18) | внешнее прерывание, вызывает `Irq4BusHandler` |
| $FE | `Isr_SCI` ($08A22) | последовательная линия: диагностика и перепрошивка (`SciInterrupt`) |
| $FF | `Isr_QSPI` ($08A3E) | последовательный периферийный интерфейс, вызывает `QspiService` |
| $11, $13, $15-$17, $44, $4A | `UnexpectedInterrupt` | не должны возникать (ниже) |
| все остальные | `Reset` | |

Обработчики прерываний, которых быть не должно (IRQ1, IRQ3, IRQ5-IRQ7, OC1, переполнение счётчика
импульсов), запрещают свой источник и переходят на `UnexpectedInterrupt`. Тот ставит по биту на
источник в `UnexpectedIrqFlags` ($00,Z) и сохраняет два слова прерванного кадра стека в $02,Z и
$04,Z. Это запись для диагностики, а не восстановление.

## Быстрый планировщик: прерывание PIT

`Isr_PIT` выполняется каждые 0,854 мс. Если `$0550,Z` не установлен, оно увеличивает
`PitTickCounter` и `LoopTickCounter`, а затем выбирает работу по младшим битам `PitTickCounter`:

| Тики | Период | Работа |
|---|---|---|
| нечётные | 1,71 мс | `HighRpmTimerPit`, `SciPitService`; `MtvTiming` и `TuneValve2Control`, если установлены биты калибровки $0335.5 / $0335.7 |
| 2 по модулю 4 | 3,42 мс | запуск цикла преобразования АЦП (ADCTL1 = $24), затем `ChargeControl2` или `ChargeControl` (бит калибровки $0338.1) |
| 4 по модулю 8 | 6,84 мс | `IacStepperDrive` |
| 0 по модулю 8 | 6,84 мс | ничего |

Затем на каждом тике: `FanPwmOutputCheck`, если установлен бит калибровки $0334.4, счётчик для $0DC0,Z и
каждые 24 тика (20,5 мс) `CcdTransmit` или `PciPitTick`, выбор по биту калибровки $032E.2.

## Фоновый планировщик: главный цикл

`MainLoop` ($0DC36) делает один проход каждые 14 тиков PIT, примерно 12,0 мс:

1. 33 подпрограммы на каждом проходе, начиная с `KickWatchdogs` и `MainLoopCounters`.
2. Одна группа подпрограмм, выбранная по младшему установленному биту `MainLoopCounter`, — та же
   схема, что в FCC:

   | Младший установленный бит | Период | Подпрограммы |
   |---|---|---|
   | 0 | 2 прохода, 24 мс | 9 (`SkimEepromSave` ... `PwmC18CircuitCheck`) |
   | 1 | 4 прохода, 48 мс | 3 (`ChargeDeficitCalc`, `BatteryVoltsUpdate`, `AsdRelayCheck`) |
   | 2 | 8 проходов, 96 мс | 13 (`SecurityState` ... `LimitReasonCode`) |
   | 3 | 16 проходов, 191 мс | 5 (`PciLinkCheck` ... `WotLeanMonitor`) |
   | 4 | 32 прохода, 383 мс | 5 (`KnockLearnDecayStep` ... `BusTempFlag`) |
   | 5 | 64 прохода, 766 мс | 2 (`FlexFaultReport`, `FuelSenderMonitor`) |
   | 6 | 128 проходов, 1,5 с | нет |
   | 7 | 256 проходов, 3,1 с | 6 (`SriMileageStore` ... `BusStatusByte`) |

3. Ещё около 60 подпрограмм на каждом проходе; одна из них выбирается битом калибровки $032E.2
   (`CcdReceive` или `PciReceive` и `QspiCheck`).
4. `CheckPowerDown`, затем ожидание, пока `LoopTickCounter` не дойдёт до 14, с вызовом
   `MeasureLoopTime`; счётчик обнуляется, и всё начинается заново.

`MainLoopCounters` ведёт и более медленные отсчёты: `Count3s` (каждые 256 проходов) и `Count191ms`
(каждые 16 проходов), оба с насыщением на $FF, а также `MainLoopPhaseMask` ($0C3B,Z). Бит n в
`MainLoopPhaseMask` установлен один раз за 2^(n+1) проходов; 127 команд проверяют его через
`BRCLR MainLoopPhaseMask,Z,#маска,...`, чтобы выполнять часть подпрограммы реже.

## Два варианта связи

Бит калибровки $032E.2 проверяется в 30 местах. В нескольких из них он выбирает между двумя наборами
подпрограмм: в главном цикле (см. выше), в прерывании PIT (`CcdTransmit` / `PciPitTick`), в
`Isr_IRQ2` (`Irq2BusHandler` / `PciIrq2Start`) и в коде сброса. Разбор приёма подтверждает, что это два
интерфейса шины автомобиля:

- `CcdReceive` принимает сообщения с однобайтовым идентификатором и одним-двумя байтами данных из
  двух буферов приёма ($89A2, $89A8). `CcdTransmit` отправляет постоянный круг сообщений, которые
  собирают небольшие подпрограммы; каждое сообщение — идентификатор, два байта данных и байт
  контрольной суммы (сумма трёх остальных). Среди сообщений: MAP, дроссель вместе с заданной
  скоростью или скоростью возобновления круиза, температура ОЖ и аккумулятора, напряжение бортсети и заданное напряжение, обороты вместе с
  заданными оборотами ХХ, барометр и температура воздуха, израсходованное топливо и импульсы пути,
  а также VIN по одному символу (`Vin01`–`Vin17`).
- `PciReceive` принимает кадры до 11 байт; младшие биты первого байта проверяются как заголовок, а
  второй байт выбирает обработчик по таблице переходов $3105A. Обработчики сохраняют те же
  значения, что и в варианте CCD. Вместе с байтом заголовка это указывает на J1850 PCI, но тип шины
  пока остаётся выводом.

Обе подпрограммы приёма ведут обмен с SKIM (иммобилайзером): сообщения $0B и $C2 несут состояние и
данные ключа (`SkimStatus`, `SkimData0`–`SkimData4`). `SkimKeyCheck` ($320D6) вычисляет ожидаемый
ключ из байтов VIN; при неверном ключе фиксируется P1685.

## Диагностика по линии SCI

`Isr_SCI` вызывает `SciInterrupt` ($3343C). Диагностические команды разбираются через таблицы
переходов по адресам $35000, $3509C, $350CC, $350DC и $35BB0. Среди них есть служба, которая
побайтно пишет принятую подпрограмму в ОЗУ по адресам $F8700-$F87FF (`DiagWriteRamByte`) и после
проверки длины, контрольной суммы и завершающего `RTS` запускает её (`DiagRunRamCode`,
`JMP $F8700`). То есть тестер может выполнить в блоке свой код без перепрошивки. Это не то же самое,
что загрузочный режим, которым пользуется `third_party/SBECBootLoader`.

По той же линии работает режим быстрой записи (`SciLogReceive`): командные байты $F2 и $F3–$F6
устанавливают биты режима в `SciLogFlags`, $FE выходит из режима; после этого каждый принятый байт
выбирает значение, которое блок отправляет в ответ (из списка адресов ОЗУ или слово со страницы
банка 3, выбранной байтами $F3–$F5). `SciRequestReceive` принимает обычные запросы
(`DiagCommand`, `DiagParam1`–`DiagParam3`); постоянная последовательность байтов ($F8, $F7, $F5,
$F3, $14), которую отслеживает `SciUnlockState`, переключает на команду $52.
