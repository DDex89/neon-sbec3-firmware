# Инструменты и сборка

Прошивка SBEC3 собирается из исходника собственными инструментами проекта для CPU16: свободных
ассемблеров с поддержкой 68HC16 нет. Дизассемблер и ассемблер используют одну таблицу команд, поэтому
сборка байт в байт проверяет оба сразу.

## Сборка

```sh
python3 tools/build.py              # собрать src/<номер детали>/ и проверить SHA-256
```

Нужны только Python 3 и исходники, образ ПЗУ не нужен. Результат пишется в `build/`. CI выполняет ту
же команду при каждом push.

Перегенерировать исходник из образа (нужно только при изменении генератора или для другого образа):

```sh
python3 tools/gen_source.py roms/05293190AC.bin src/05293190AC
python3 tools/survey.py roms/*.bin  # заголовок, контрольная сумма и семейства всех образов
```

`EDIVS` делит знаковую пару E:D на знаковый IX. Частное помещается
в IX, остаток в D. Симулятор учитывает условие округления во флаге C
и останавливает выполнение при нулевом делителе или выходе частного
за знаковый 16-битный диапазон. Доставка исключения и результаты
переполнения остаются за пределами модели. `simtest.py` проверяет
13 арифметических случаев и четыре остановки.
[Руководство CPU16, EDIVS на стр. 6-102](https://www.nxp.com/docs/en/reference-manual/CPU16RM.pdf)

## Таблица команд

Таблица извлечена из руководства CPU16 Reference Manual (CPU16RM/AD): таблица 6-36 «Instruction Set
Summary» даёт мнемонику, режим адресации, код и формат операндов, а таблицы 7-2 – 7-5 перечисляют
четыре страницы кодов по порядку. Оба источника совпадают по всем 842 кодам (246 на странице 0, 186 на
странице 1 за префиксом $17, 202 на странице 2 за $27, 208 на странице 3 за $37). Каждая команда
занимает целое число 16-битных слов (2, 4 или 6 байт), как и требует CPU16.

Для инструментов важны две особенности CPU16:

- Смещение ветвления отсчитывается от адреса команды **плюс 6** из-за конвейера предвыборки на три
  слова (CPU16RM 7.3). Сложение 20-битное (PK : PC).
- `JMP` и `JSR` принимают 20-битный адрес (EXT20) или 20-битное смещение от индексного регистра (IND20).

## Синтаксис

Близок к синтаксису Motorola, но ширина каждого операнда задана явно, чтобы ассемблер воспроизводил
исходную кодировку:

| Режим | Пример | Примечание |
|---|---|---|
| Непосредственный | `LDAA #$12`, `LDD #$1234` | 2 hex-цифры = 8 бит, 4 = 16 бит |
| Индексный | `LDAA $12,Z`, `STD $7A04,Z`, `JMP $2CE5E,X` | 2 цифры = IND8, 4 = IND16 (без знака), 5 = IND20 |
| Расширенный | `CMPA $19DC`, `JSR MainLoopCounters` | 4 цифры = EXT (банк из EK), 5 цифр или метка = EXT20 |
| Смещение аккумулятором | `LDAA E,X` | |
| Ветвление | `BRA L08100`, `LBNE L08432` | Bcc — 8-битное смещение, LBcc — 16-битное |
| Битовые операции | `BSET $0A,Z,#$02`, `BRSET $0332,#$08,L1B57A` | адрес, маска, цель |
| Пересылка | `MOVB $05,X+,$1234`, `MOVW $1234,$5678` | |
| Список регистров | `PSHM D,E,X,Y,K`, `PULM K,X,D` | порядок в списке не важен |
| Символ | `INC >PitTickCounter,Z`, `STD >SYNCR,Z` | `>` задаёт 16-битную, `<` 8-битную кодировку, как в оригинале |

## Анализ потока управления

`tools/analyse.py` начинает с точки входа и векторов исключений, идёт по ветвлениям, вызовам и
переходам EXT20 и разбирает **таблицы переходов**, на которые ведёт индексный `JMP`:

- `JMP $база,X` или `JMP $база,Y` по ряду 4-байтных `JMP $xxxxx`, ряду 4-байтных `JSR $xxxxx` или
  6-байтных пар `JSR` / `BRA`. Предшествующий `CMPB #n` ограничивает число элементов. Элемент может
  быть короткой встроенной вставкой, кончающейся `RTS`; если элемент 0 не переход, а элемент 1 —
  переход, вызывающий код индекс 0 не использует, и таблица начинается с элемента 1.
- `LDX #база` ... `CPX #предел` ... `JMP $00000,X`: элементы между двумя границами.

В 05293190AC так находится 43 370 команд (144 074 байта) и 21 таблица переходов, неразобранных
косвенных переходов нет. Один переход ведёт в ОЗУ ($F8700): это диагностическая служба, которая
выполняет код, загруженный по линии SCI (см. [architecture.md](architecture.md)); он учитывается
отдельно, а не как ошибка.

## Имена и заметки

`tools/gen_source.py` берёт имена из `annotations/`:

| Файл | Содержимое |
|---|---|
| `labels.json` | метки кода эталона |
| `vectors.json` | имена векторов исключений |
| `ram.json` | переменные ОЗУ как смещения от Z |
| `hc16z_registers.json` | регистры модулей 68HC16Z (из руководства по серии Z) |
| `routines.md` | заметки, которые печатаются над подпрограммами |
| `analysis.json` | где Z не база ОЗУ; переходы в ОЗУ |

Остальные метки генерируются: `Sub_xxxxx` для целей вызовов, `JumpTable_xxxxx`, `Lxxxxx` для прочих.
Операнд `$xxxx,Z` превращается в `ИМЯ,Z`, если смещение — известная переменная ОЗУ или регистр;
байтовое обращение к младшей половине 16-битного регистра получает суффикс `_L` (`SCDR_L` — младший
байт SCDR). Использованные символы пишутся в `00_equates.asm`. У каждой подпрограммы есть заголовок с
её векторами, вызывающими подпрограммами и заметками.

## Проверка по опорным адресам 2GNT

Адреса калибровки, которые 2GNT приводит для 05293190AC, сверены с анализом. Все они лежат вне кода, и
большинство код загружает как указатели на таблицы:

| Адрес | Название у 2GNT | Кто обращается |
|---|---|---|
| $1BFA | опережение, частичный дроссель | `LDX #$1BFA` по адресу $1D2A6 |
| $1FAF | опережение, WOT | `LDX #$1FAF` по адресу $1D2C4 |
| $08F8 | шкала Y частичного дросселя | `LDX #$08F8` по адресам $10F46, $1DA42 и другим |
| $0904 | шкала Y WOT | `LDX #$0904` по адресу $1D2B4 |
| $24AB | порог датчика детонации | `LDX #$24AB` по адресу $1F360 |
| $0B9E | масштаб безвозвратной топливной системы | `LDX #$0B9E` по адресам $1090A, $10AFC |
| $0B76 | мёртвое время форсунок | `LDX #$0B76` по адресу $10020 |
| $19DC | ограничитель оборотов MTX / PN | `CMPA $19DC` по адресу $101F8, `LDAB $19DC` по адресу $20C86 |
| $4052 | массив атрибутов ошибок | `ADDD #$4052` по адресу $20A8C, `LDX #$4052` по адресу $326BE и другим |
| $2684 | целевые обороты холостого хода | `LDX #$2684` по адресу $1B344 |

Топливные таблицы ($0BF6, $0F6C) и их константы смещения MAP и K ($0B92-$0B95) напрямую не
загружаются: их адреса встречаются как слова данных около $11F4E-$11FC2, то есть к ним обращаются через
таблицу описателей. Это тема этапа 4.

## Модель памяти по коду

Подпрограмма сброса ставит SK = ZK = $F, SP = $8FFE и IZ = $8000, а EK = 0. Отсюда:

- **Z указывает на $F8000, начало ОЗУ.** `$xx,Z` и `$0xxx,Z` адресуют ОЗУ ($F8000-$F8FFF у блоков на
  4 КБ); `$7xxx,Z` попадает в регистры модулей по адресам $FFxxx, например `$7A00,Z` = $FFA00 (SIM) и
  `$791F,Z` = $FF91F (таймер общего назначения). Переменные ОЗУ называются по смещению от Z.
- **Расширенные адреса (`$xxxx`, EK = 0) указывают в банк 0**, то есть в калибровку. Код в банках 1-3
  читает калибровку обычными командами вида `LDAA $19DC`.
- XK и YK переключаются часто (`TBXK` 92 раза, `TBYK` 117 раз), так что для индексного доступа к
  таблицам в других банках на следующих этапах понадобится отслеживание регистров.
