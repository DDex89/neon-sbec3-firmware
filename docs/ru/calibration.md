# Калибровка

Как устроена калибровка эталонного образа **05293190AC**: где она лежит, форматы таблиц и
подпрограммы выборки, которые их читают, единицы и как получается длительность впрыска. Полный
список таблиц — в сгенерированном каталоге [docs/catalogue/05293190AC.md](../catalogue/05293190AC.md);
в исходнике каждая таблица выведена отдельным блоком с комментарием (заголовок, ось, по строке
на ряд).

## Где лежит калибровка

Калибровка находится в банке 0, между заголовком по $00202 и началом кода по $08000. Код сброса
ставит EK = 0, поэтому программа читает её обычными расширенными адресами (`CMPA $19DC`). Записей
туда в коде нет: область только для чтения.

Код обращается к ней двумя способами:

- **Таблицы** передаются в X одной из четырёх подпрограмм выборки (`LDX #таблица`,
  `JSR Lookup2D`). Подпрограммы выборки обнуляют XK, так что все таблицы лежат в банке 0. Так
  находится 411 таблиц в диапазоне $0398-$ABD7 (две маленькие — среди кода банка 0).
- **Константы** читаются напрямую: 1455 разных адресов, в основном через `CMPA`/`CMPB` (пороги),
  `LDAA`/`LDAB` и `LDD`/`CPD` (16-битные значения). Биты конфигурации около $0328-$0338
  проверяются командами `BRSET`/`BRCLR`. Названы пока только подтверждённые константы.

## Форматы таблиц

Все значения — байты. Форматы следуют из подпрограмм выборки:

| Формат | Подпрограмма | Устройство | Тип 2GNT |
|---|---|---|---|
| 2D | `Lookup2D` ($0C08E) | n, флаги, затем n пар (x, y), x по возрастанию | C |
| 2D (y, x) | `Lookup2DRev` ($0C36A) | n, не используется, затем n пар (y, x) | |
| 3D | `Lookup3D` ($0C214) | ряды, столбцы, флаг знака, ось столбцов (байт на столбец), значения по рядам | A |
| 3D без оси | `Lookup3DNorm` ($0C28C) | ряды, столбцы, флаг знака, значения по рядам | B |

Таблица неисправностей — ниже (тип D у 2GNT).

**2D.** Вход сравнивается со значениями x; между двумя точками результат интерполируется
линейно, за пределами диапазона берётся первое или последнее y. Байт флагов задаёт арифметику: $80
— без знака (320 из 353 таблиц), $20 — y со знаком, $10 — ступеньки без интерполяции, $40 — нулевой
y считается как 256. За многими 2D-таблицами идут неиспользуемые байты до ячейки в 12 байт (пять
точек); можно ли удлинить таблицу в это место, надо проверять для каждой таблицы отдельно.

**3D.** Вход рядов — это *позиция* 0-255, равномерно распределённая по рядам (ряд = позиция x
(рядов-1) / 256). Обычно она берётся из 2D-таблицы масштаба, которая переводит MAP в эту позицию:
таблицы частичного дросселя используют `PartThrottleMapScale`, таблицы полного дросселя —
`WotMapScale`. Вход столбцов ищется по записанной оси столбцов (`Lookup3D`) или тоже является
позицией 0-255 (`Lookup3DNorm`). Результат интерполируется в обоих направлениях. Размеры в этом
образе: 17 x 17, 9 x 17, 9 x 9, 5 x 9 и 5 x 5.

Флаг знака ($FF) означает значения в дополнительном коде; в исходнике они показаны отрицательными
десятичными числами.

## Единицы

Названия единиц в `annotations/tables.json` и в комментариях исходника:

| Единица | Перевод |
|---|---|
| rpm32 | об/мин = x * 32 |
| rpm8 | об/мин = x * 8 |
| kpa | кПа = x / 2,428 (у 2GNT: торр = x / 0,3237) |
| spark | градусы до ВМТ = x / 2 |
| tempc | °C = x - 128 (°F = (x - 128) * 1,8 + 32) |
| volt16 | вольты = x / 16,19 |
| volt51 | вольты = x / 51 |
| pwus32 | микросекунды = x * 32 |
| mult256 | множитель = x / 256 |
| pos256 | позиция 0-255 по рядам 3D-таблицы |
| fuelcorr | топливный множитель = 1 + x / 256, x со знаком: -128 даёт 0,5, +127 даёт 1,496 |

Они те же, что у блока FCC 1995 года и на страницах 2GNT.

## Известные таблицы и константы

| Адрес | Имя | Содержимое |
|---|---|---|
| $08F8 | PartThrottleMapScale | MAP в позицию ряда, частичный дроссель (УОЗ и топливо) |
| $0904 | WotMapScale | MAP в позицию ряда, полный дроссель (УОЗ и топливо) |
| $1BFA | PartThrottleSpark | 17 x 17, обороты x MAP, УОЗ |
| $1FAF | WotSpark | 9 x 17, со знаком |
| $0BF6 | PartThrottleFuel | 17 x 17, со знаком, топливная поправка |
| $0F6C | WotFuel | 9 x 17, со знаком, топливная поправка |
| $0B92, $0B93 | PartThrottleFuelK, PartThrottleFuelMapOffset | константы базовой длительности впрыска, частичный дроссель |
| $0B94, $0B95 | WotFuelK, WotFuelMapOffset | то же для полного дросселя |
| $0B76 | InjectorDeadTime | напряжение бортсети в мёртвое время форсунки |
| $0B9E | ReturnlessFuelScale | топливный множитель для системы без обратки |
| $24AB | KnockThreshold | порог датчика детонации по оборотам |
| $2684 | IdleTargetRpm | целевые обороты ХХ по температуре ОЖ |
| $19DC, $19DE | RevLimit, RevLimitAlt | два ограничения оборотов (6048 и 7008 об/мин), выбор по биту 5 в $0C31,Z |
| $19E1, $19E3 | SpeedLimit, SpeedLimitMinRpm | ограничитель скорости, включается битом калибровки $0337.5 |
| $4052 | FaultTable | 256 строк неисправностей |

Всё это сверено с кодом: каждая таблица читается там, где указывает 2GNT, и в описанном формате. Одна
поправка: 2GNT показывает ограничитель оборотов двумя ячейками с $19DB (возврат и предел), но в
$19DB лежит $FF и код его не читает; обороты сравниваются с $19DC или с $19DE.
2GNT называет топливные таблицы «msec»; по коду видно, что это поправки к длительности впрыска,
посчитанной по MAP (следующий раздел).

## Названия таблиц

У каждой таблицы эталона есть имя. 142 названы вручную по коду (и сверены с 2GNT, где они там есть),
в том числе весь путь топлива, описанный ниже, поправки УОЗ, накопление катушки, цели ХХ и кривые
датчиков. Остальные 268 имеют
**структурные имена**, которые даёт `tools/autoname.py`; в `annotations/tables.json` они помечены
`"auto": true` (в каталоге — звёздочкой):

- приставка — подсистема, определённая по подпрограмме, которая читает таблицу, и по запланированной
  подпрограмме над ней;
- затем входы: `Coolant`, `AirTemp`, `Rpm`, `SegRpm`, `Map`, `Baro`, `Vacuum`, `Throttle`, `Speed`,
  `Volts`, `StartCoolant`, `Time`, `IdleTarget`, `Trim`, `O2`; `V0A91` — переменная ОЗУ, у которой
  ещё нет имени, `Cal` — калибровочная константа, `Scaled` — результат таблицы масштаба;
- номер, если имя повторяется.

Так, `AccelFuelCoolant2` — вторая таблица ускорительного обогащения, выбираемая по температуре ОЖ. В
описании каждой таблицы сказано, какая подпрограмма её читает, какие у неё входы и куда идёт
результат. Структурное имя говорит, к чему относится таблица и от чего зависит, но ещё не говорит,
что именно она делает.

| Приставка | Подсистема | Категория | Таблиц |
|---|---|---|---|
| Fuel, FuelEvent | расчёт топлива в главном цикле и на каждом опорном событии | Fuel | |
| FuelCut | отсечка топлива: ограничения оборотов и скорости, торможение двигателем | Fuel | |
| AccelFuel | ускорительное обогащение (скорость изменения дросселя и MAP) | Fuel | |
| AfterStartFuel | обогащение после пуска (время после пуска x температура ОЖ) | Fuel | |
| CrankFuel | топливо при прокрутке | Fuel | всего 112 |
| O2 | обратная связь по кислородным датчикам и адаптация | Closed loop | 7 |
| Idle | управление холостым ходом | Idle | 89 |
| Spark, Knock | УОЗ и управление по детонации | Spark | 89 |
| Misfire, Diag | монитор пропусков зажигания (времена сегментов коленвала) и другие мониторы OBD | Diagnostics | 36 |
| Sensor | обработка датчиков | Sensors | 20 |
| SpeedCtl | круиз-контроль; вероятно | Speed control | 11 |
| Start | инициализация при сбросе | Startup | 5 |
| FlexLearn | обучение доли этанола (flex fuel) | Fuel | |
| Fan | управление вентилятором радиатора (реле и ШИМ) | Cooling fan | 6 |
| Egr | управление EGR; вероятно | EGR | 8 |
| AcCtl | управление муфтой кондиционера; вероятно | A/C | 4 |
| Purge | управление продувкой адсорбера; вероятно | EVAP purge | 15 |
| Event, Pit, Sys<адрес> | ещё не определено; названо по верхней подпрограмме | Other | 8 |

Подсистемы определены по коду: например, группа ХХ пишет и использует цель ХХ ($0300,Z, из
`IdleTargetRpm`), группа пропусков ведёт времена сегментов по цилиндрам, группа детонации читает
`KnockThreshold`, группа обратной связи владеет кратковременными коррекциями. Круиз-контроль выведен
из его автомата состояний по скорости и оборотам и помечен как вероятный.

Повторный запуск `python3 tools/autoname.py` после того, как названы новые переменные ОЗУ или
подпрограммы, обновляет структурные имена; ручные имена (записи без `"auto"` и переопределения в
скрипте) остаются.

## Длительность впрыска

`CalcFuelPulse` ($11F40) вызывается из прерывания захвата 1, то есть на каждом опорном событии:

1. Частичный или полный дроссель выбирается битом 5 в `$0771,Z`; от него зависят константы,
   таблица масштаба и топливная таблица.
2. Базовая длительность = (Map - MapOffset) x (256 + K) / 16, или ноль, если MAP ниже смещения. При
   установленном бите калибровки $0337.2 MAP сначала поднимается до нижней точки масштаба
   частичного дросселя.
3. Топливная таблица даёт знаковое значение v (ряды — по MAP через таблицу масштаба, столбцы — по
   `EngineRpm`, старший байт которого — обороты / 32); базовая длительность умножается на 1 + v / 256.
4. Прибавляется `$080E,Z`, результат пишется в `FuelPulse` ($07E2,Z) и `$04F6,Z`.

То есть топливные таблицы работают как поправка наполнения к линейной модели по MAP, а две
константы задают наклон и нулевую точку. Мёртвое время, температурные и прочие поправки
применяются в других местах (этап 5).

`InjectorDeadTime` выбирается по входу `$0A51,Z`. 2GNT приводит исправление, которое меняет вход на
`$0A50,Z` (`BatteryVolts`); кто пишет в $0A51, пока не проверено.

## Поправки топлива

Кроме базовой длительности, код строит такие поправки (имена — как в исходнике):

| Часть | Подпрограмма | Таблицы | Результат |
|---|---|---|---|
| Обогащение при прогреве | `Sub_10D5E` | `WarmupMapCoolant` (MAP x ОЖ), `WarmupMapCoolantLowSpeed` (ниже порога скорости), `WarmupRpmCoolantIdle` (дроссель закрыт), `WarmupCoolantAdder` (WOT), множители по барометру, времени работы и оборотам | `WarmupFuelFactor` ($07E4,Z) |
| Затухание после пуска | `Sub_10D5E` | `AfterStartTimeScale`, `AfterStartDecay` (время после пуска x температура пуска) | часть множителя прогрева |
| Холодный отстой | `Sub_10D5E` | `ColdSoakMapCoolant`, когда ОЖ при пуске близка к $0A5E,Z | `$07E7,Z` |
| Прокрутка | `Sub_123C0` | `CrankBasePulse` (этанол x температура прокрутки), уменьшения по оборотам, $0769,Z и барометру с весами по ОЖ; `CrankVacuumFactor` | `CrankPulse` ($0766,Z) |
| Резкое открытие дросселя | `Sub_107EA` | `TipInMatrix` (9 x 9: ряды по открытию, столбцы по шагу дросселя), множители по ОЖ, воздуху и барометру | `TipInFuel` ($07C6,Z) |
| Обогащение по скорости MAP и дросселя | `Sub_106EC` | `AccelMapGainCoolant`, `AccelTpsRateLimit`, `AccelTpsCoolantFactor`, члены по барометру, `AccelRpmFactor` | `AccelMapGain`, `AccelTpsFuel`, `AccelFactor` |
| Обеднение при сбросе газа | `Sub_12142` | `DecelLeanAirflow` (обороты x дроссель), множители по ОЖ, времени, оборотам, MAP и барометру | `DecelLeanFuel` ($07C2,Z) |
| Отсечка при торможении двигателем | `Sub_10036` | `DecelCutMapThreshold`, `DecelCutDelay`, минимальные обороты по ОЖ; ограничения оборотов и скорости | флаги `$0770,Z`, `DecelCutRpmFactor` |
| Уменьшение топлива при сбросе | `Sub_104AE` | `DecelMapRpmLimit` (MAP x обороты) | `DecelFuelFactor` ($077A,Z) |
| Обогащение при долгом WOT | `Sub_102FE` | `WotTimeEnrichMax` | `WotTimeEnrich` ($07AA,Z) |
| Обогащение на ХХ | `Sub_11074` | время работы, этанол x температура воздуха при пуске, время стоянки | `IdleEnrichFactor` ($07DA,Z) |
| Обогащение горячего двигателя | `Sub_111E0` | `HotEngineEnrich` | `$0811,Z` |
| Температура воздуха | `Sub_10AEC` | `FuelAirTempCorr` с весами по оборотам и MAP | множитель топлива |
| Фильтры MAP и дросселя | `Sub_1204A` | коэффициенты фильтров при росте и падении MAP и дросселя по ОЖ при пуске | `MapFilterCoef`, `TpsFilterCoef` |

**Flex fuel.** Программа поддерживает машины на смесевом топливе: `Sub_2C7FE` следит за уровнем
топлива (`FuelLevel`, $0A8E,Z), чтобы заметить заправку, а код обучения (`FlexLearn...`, около
`Sub_17000`) определяет долю этанола по коррекциям кислородных датчиков (`FlexEthanolLearned` $0197,Z,
0-170, и `FlexEthanol` $0198,Z). Доля этанола затем выбирает ряды в топливных таблицах и таблицах УОЗ
`Flex...` и в таблице прокрутки. Включается битом калибровки $032C.6; в 05293190AC (бензиновая
машина) flex-таблицы нейтральны.

## Таблица неисправностей

`FaultTable` ($4052) — 256 строк по 10 байт:

| Байт | Содержимое |
|---|---|
| 0 | номер строки |
| 1 | счётчик срабатываний |
| 2 | блинк-код (BCD, как мигает лампа Check Engine) |
| 3 | биты атрибутов |
| 4, 5 | маска и смещение байта бита неисправности в массиве битов неисправностей |
| 6, 7 | P-код (BCD): $03 $40 = P0340 |
| 8, 9 | не используются (ноль) |

P-код есть в 83 строках; список — в каталоге. Есть коды цилиндров 5 и 6 (P0205, P0206, P0355),
так что программа рассчитана и на шестицилиндровые двигатели.

## Инструменты

```sh
python3 tools/caltables.py roms/05293190AC.bin        # список найденных таблиц
python3 tools/catalogue.py roms/05293190AC.bin docs/catalogue/05293190AC.md
```

`tools/caltables.py` находит подпрограммы выборки по байтам их кода, поэтому работает и на других
образах на 256 КБ: 397 таблиц в 05269833AH, 404 в 05269833AI и 05269834AJ, 462 в 05032017AA. У
семейств на 128 КБ код выборки другой, это тема этапа 5. Имена и единицы берутся из
`annotations/tables.json` и применяются только к эталону.

## Открытые вопросы

- У 268 таблиц пока только структурные имена; точные названия требуют чтения каждой подпрограммы.
- 1455 констант, читаемых напрямую, пока не описаны по одной.
- Семь выборок, где адрес таблицы берётся из указателя, а не из `LDX #` (например, по адресам
  $146E4 и $1974A), пока не прослежены.
