# Калибровка

Как устроена калибровка эталонного образа **05293190AC**: где она лежит, форматы таблиц и
подпрограммы выборки, которые их читают, единицы и как получается длительность впрыска. Полный
список таблиц — в сгенерированном каталоге [docs/catalogue/05293190AC.md](../catalogue/05293190AC.md);
в исходнике каждая таблица выведена отдельным блоком с комментарием (заголовок, ось, по строке
на ряд).

## Где лежит калибровка

Калибровка находится в банке 0, между заголовком по $00202 и началом кода по $08000. Код сброса
ставит EK = 0, поэтому программа читает её обычными расширенными адресами (`CMPA $19DC`). Записей
туда в коде нет: область только для чтения.

Код обращается к ней двумя способами:

- **Таблицы** передаются в X одной из четырёх подпрограмм выборки (`LDX #таблица`,
  `JSR Lookup2D`). Подпрограммы выборки обнуляют XK, так что все таблицы лежат в банке 0. Так
  находится 411 таблиц в диапазоне $0398-$ABD7 (две маленькие — среди кода банка 0).
- **Константы** читаются напрямую: 1448 разных адресов, в основном через `CMPA`/`CMPB` (пороги),
  `LDAA`/`LDAB` и `LDD`/`CPD` (16-битные значения). Биты конфигурации $0328-$0340 проверяются
  командами `BRSET`/`BRCLR`. См. раздел «Константы и биты настроек».

## Форматы таблиц

Все значения — байты. Форматы следуют из подпрограмм выборки:

| Формат | Подпрограмма | Устройство | Тип 2GNT |
|---|---|---|---|
| 2D | `Lookup2D` ($0C08E) | n, флаги, затем n пар (x, y), x по возрастанию | C |
| 2D (y, x) | `Lookup2DRev` ($0C36A) | n, не используется, затем n пар (y, x) | |
| 3D | `Lookup3D` ($0C214) | ряды, столбцы, флаг знака, ось столбцов (байт на столбец), значения по рядам | A |
| 3D без оси | `Lookup3DNorm` ($0C28C) | ряды, столбцы, флаг знака, значения по рядам | B |

Таблица неисправностей — ниже (тип D у 2GNT).

**2D.** Вход сравнивается со значениями x; между двумя точками результат интерполируется
линейно, за пределами диапазона берётся первое или последнее y. Байт флагов задаёт арифметику: $80
— без знака (320 из 353 таблиц), $20 — y со знаком, $10 — ступеньки без интерполяции, $40 — нулевой
y считается как 256. За многими 2D-таблицами идут неиспользуемые байты до ячейки в 12 байт (пять
точек); можно ли удлинить таблицу в это место, надо проверять для каждой таблицы отдельно.

**3D.** Вход рядов — это *позиция* 0-255, равномерно распределённая по рядам (ряд = позиция x
(рядов-1) / 256). Обычно она берётся из 2D-таблицы масштаба, которая переводит MAP в эту позицию:
таблицы частичного дросселя используют `PartThrottleMapScale`, таблицы полного дросселя —
`WotMapScale`. Вход столбцов ищется по записанной оси столбцов (`Lookup3D`) или тоже является
позицией 0-255 (`Lookup3DNorm`). Результат интерполируется в обоих направлениях. Размеры в этом
образе: 17 x 17, 9 x 17, 9 x 9, 5 x 9 и 5 x 5.

Флаг знака ($FF) означает значения в дополнительном коде; в исходнике они показаны отрицательными
десятичными числами.

## Единицы

Названия единиц в `annotations/tables.json` и в комментариях исходника:

| Единица | Перевод |
|---|---|
| rpm32 | об/мин = x * 32 |
| rpm8 | об/мин = x * 8 |
| kpa | кПа = x / 2,428 (у 2GNT: торр = x / 0,3237) |
| spark | градусы до ВМТ = x / 2 |
| tempc | °C = x - 128 (°F = (x - 128) * 1,8 + 32) |
| volt16 | вольты = x / 16,19 |
| volt51 | вольты = x / 51 |
| pwus32 | микросекунды = x * 32 |
| mult256 | множитель = x / 256 |
| pos256 | позиция 0-255 по рядам 3D-таблицы |
| fuelcorr | топливный множитель = 1 + x / 256, x со знаком: -128 даёт 0,5, +127 даёт 1,496 |

Они те же, что у блока FCC 1995 года и на страницах 2GNT.

| Адрес | Имя | Содержимое |

| $0904 | WotMapScale | MAP в позицию ряда, полный дроссель (УОЗ и топливо) |
| $1BFA | PartThrottleSpark | 17 x 17, обороты x MAP, УОЗ |
| $1FAF | WotSpark | 9 x 17, со знаком |

| $0B92, $0B93 | PartThrottleFuelK, PartThrottleFuelMapOffset | константы базовой длительности впрыска, частичный дроссель |
| $0B94, $0B95 | WotFuelK, WotFuelMapOffset | то же для полного дросселя |
| $0B76 | InjectorDeadTime | напряжение бортсети в мёртвое время форсунки |
| $0B9E | ReturnlessFuelScale | топливный множитель для системы без обратки |
| $24AB | KnockThreshold | порог датчика детонации по оборотам |

| $19DC, $19DE | RevLimit, RevLimitAlt | два ограничения оборотов (6048 и 7008 об/мин), выбор по биту 5 в $0C31,Z |

| $4052 | FaultTable | 256 строк неисправностей |

Всё это сверено с кодом: каждая таблица читается там, где указывает 2GNT, и в описанном формате. Одна
поправка: 2GNT показывает ограничитель оборотов двумя ячейками с $19DB (возврат и предел), но в
$19DB лежит $FF и код его не читает; обороты сравниваются с $19DC или с $19DE.
2GNT называет топливные таблицы «msec»; по коду видно, что это поправки к длительности впрыска,
посчитанной по MAP (следующий раздел).

## Холостой ход и УОЗ

Регулятором холостого хода (РХХ) управляют несколько подпрограмм, все они заканчиваются в подпрограмме шага `IacSetTarget`:

| Подпрограмма | Что делает | Таблицы |
|---|---|---|
| `IdleRpmTarget` | цель холостого хода ($0300,Z): таблица по ОЖ (вариант P/N), добавки при провале оборотов на передаче, при горячем воздухе на впуске и плавно нарастающая цель по температуре АКБ и времени работы | `IdleTargetRpm*`, `IdleTargetDip*`, `IdleTargetHotAirAdder`, `IdleBattTemp*` |
| `IdleRpmLoop` | замкнутый контур по оборотам: член ошибки (грубый/точный, P/N), фильтр скорости, зона нечувствительности по MAP и ОЖ, интегратор, который делает шаги РХХ на открытие или закрытие | `IdleErrorTerm*`, `IdleRateFilterCoolant`, `IdleDeadband*`, `IdleStep*` |
| `IdleMapTargetCalc` | замкнутый контур по MAP: цель MAP на холостом ($031E,Z) из базы, времени, ОЖ, оборотов и атмосферного давления, затем шаги РХХ по ошибке MAP | `IdleMap*`, `IacMap*Step*` |
| `IacBaseCalc` | базовое положение РХХ по атмосферному давлению и цели, цель при накате, скважность обмотки возбуждения генератора, включение кондиционера | `IacBase*`, `IacCoast*`, `IacFieldDuty*`, `IacAcEngageAdder` |
| `IdleTargetControl`, `GearStateUpdate` | события: переключение передачи (задержка, длительность, шаг; варианты A/C и P/N), просадка и провал оборотов, включение муфты кондиционера, цель при движении | `IacGear*`, `IacDroop*`, `IacDipKick*`, `IacAcKick*`, `IacRoll*`, `ShiftIdle*` |
| `IacChargeStepCalc` | дополнительный воздух, когда напряжение АКБ держится ниже цели зарядки | `IacChargeStep` |
| `IacCrankControl` | положение РХХ при прокрутке и в режиме пуска | `IacCrankCoolant`, `IacRunUpCoolant` |

Поправки УОЗ помимо базовых таблиц:

| Подпрограмма | Что делает | Таблицы |
|---|---|---|
| `SurgeControl`, `SurgeFilters` | рывки трансмиссии: ступенчатое уменьшение УОЗ по ускорению и рывку оборотов (полосовой фильтр оборотов по сегментам), с весом по передаче (отношение оборотов к скорости), росту MAP и ОЖ | `Surge*` |
| `TipInSparkControl` | уменьшение УОЗ при резком открытии дросселя у холостого, по росту дросселя и температуре воздуха | `TipInRetard*` |
| `SpeedDampControl` | гашение рывков на малой скорости: П, Д и И по отклонению оборотов от ожидаемых для скорости | `SpeedRpmRef*`, `SpeedDamp*` |
| `IdleSparkCalc` | УОЗ холостого хода по ошибке оборотов | `IdleSpark*` |
| `AcSparkRate`, `AcClutchSpark` | поправка УОЗ вокруг включения муфты кондиционера | `AcEngageSpark*`, `AcClutchSpark*`, `AcSpark*` |
| `O2SparkTrimCalc` | изменение УОЗ по отклонению кратковременной коррекции топлива | `O2SparkTrim*` |
| `EgrSparkCalc` | добавка при работающем EGR (17x17) | `EgrSpark` |
| `DwellLookup` | время накопления катушки по напряжению АКБ | `DwellBattery*` |

Управление по детонации обучает уровень шума по диапазонам оборотов (`KnockNoise*`), работает выше
порога MAP (`KnockMapThreshold*`) и ограничивает уменьшение УОЗ по оборотам и MAP
(`KnockRetardMax*`, `KnockRetardLimit`).

Часть этих выводов сделана по тому, как код использует переменную, а не по документации:
температура АКБ ($0A5A,Z, по ней считается цель зарядки), скважность обмотки возбуждения генератора
($032E,Z, счёт заполнения входа CS2 $106E бит 5) и датчик кондиционера ($0A88,Z, вероятно давление
хладагента) определены именно так.

## Константы и биты настроек

`tools/constants.py` находит каждый байт или слово, которое код читает напрямую расширенной
адресацией и которое не входит в таблицу: в 05293190AC их 1448 (1263 байта, 181 слово, 4 длинных),
среди них 21 байт настроек, проверяемый `BRSET`/`BRCLR` (используется 120 битов). Они хранятся
вместе с таблицами в `scalars` файла `annotations/tables.json`, поэтому в исходниках видно
`CMPA >IdleCoolantMin` вместо `CMPA $2853`, каталог показывает их со значением и физической
величиной, в XDF они есть как константы (а каждый бит настроек — как флаг), а перенос передаёт их
другим образам (от 239 в семействе A до 1404 в семействе E).

Все 120 используемых битов настроек описаны в `annotations/bits.json`. Полярность взята из кода:
большинство битов включают функцию (`BRCLR` обходит её, когда бит сброшен), несколько — выключают
(например, $033A.7 отключает проверку всплеска оборотов на холостом ходу, $0328.0 — обработку SKIM).
Биты, которые лишь выбирают одну из двух ветвей без ясного назначения, описаны как "selects a branch
in ...". Достоверно установлены: $032C.7 — замкнутый контур выключен, $032C.6 — гибкое топливо,
$032E.6 — механическая коробка, $032E.2 — шина PCI вместо CCD, $032F.7-4 — какие датчики O2
установлены (верхние 1 и 2, нижние 1 и 2) и $033F.7-4 — соответствующие мониторы подогрева. В XDF
этот текст стоит в описании каждого флага.

Для каждой константы скрипт смотрит, как она используется: что было в регистре перед сравнением,
сложением или вычитанием (`LDAA >CoolantTemp,Z`, затем `CMPA $2853`), или с чем сравнивается и
куда записывается загруженное значение. Отсюда единица (температура, обороты, кПа, вольты) и
структурное имя: приставка таблиц той же подпрограммы или подсистемы, переменная и роль (`Thresh`
для сравнения, `Adder`, `Offset`, `Factor`, `Init` для значения, записываемого в ОЗУ, `Value` в
остальных случаях), с номером при повторе. Теперь у всех 1 448 констант есть ручные имена по коду,
который их читает; если назначение не вполне ясно, в описании стоит «вероятно». Структурное имя и
звёздочка в каталоге остаются только у констант, найденных в новом образе и ещё не названных. Обороты-слова имеют единицу `rpmw`
(об/мин = x / 8).

Байты настроек $0328-$0340 — общая конфигурация. Определённые пока биты и их состояние в
05293190AC:

## Длительность впрыска

`CalcFuelPulse` ($11F40) вызывается из прерывания захвата 1, то есть на каждом опорном событии:

1. Частичный или полный дроссель выбирается битом 5 в `$0771,Z`; от него зависят константы,
   таблица масштаба и топливная таблица.
2. Базовая длительность = (Map - MapOffset) x (256 + K) / 16, или ноль, если MAP ниже смещения. При
   установленном бите калибровки $0337.2 MAP сначала поднимается до нижней точки масштаба
   частичного дросселя.
3. Топливная таблица даёт знаковое значение v (ряды — по MAP через таблицу масштаба, столбцы — по
   `EngineRpm`, старший байт которого — обороты / 32); базовая длительность умножается на 1 + v / 256.
4. Прибавляется `$080E,Z`, результат пишется в `FuelPulse` ($07E2,Z) и `$04F6,Z`.

То есть топливные таблицы работают как поправка наполнения к линейной модели по MAP, а две
константы задают наклон и нулевую точку. Мёртвое время, температурные и прочие поправки
применяются в других местах (этап 5).

`InjectorDeadTime` выбирается по входу `$0A51,Z`. 2GNT приводит исправление, которое меняет вход на
`$0A50,Z` (`BatteryVolts`); кто пишет в $0A51, пока не проверено.

## Поправки топлива

Кроме базовой длительности, код строит такие поправки (имена — как в исходнике):

| Часть | Подпрограмма | Таблицы | Результат |
|---|---|---|---|

| Холодный отстой | `WarmupFuel` | `ColdSoakMapCoolant`, когда ОЖ при пуске близка к $0A5E,Z | `$07E7,Z` |
| Прокрутка | `CrankFuel` | `CrankBasePulse` (этанол x температура прокрутки), уменьшения по оборотам, $0769,Z и барометру с весами по ОЖ; `CrankVacuumFactor` | `CrankPulse` ($0766,Z) |
| Резкое открытие дросселя | `TipInFuelControl` | `TipInMatrix` (9 x 9: ряды по открытию, столбцы по шагу дросселя), множители по ОЖ, воздуху и барометру | `TipInFuel` ($07C6,Z) |
| Обогащение по скорости MAP и дросселя | `AccelEnrichFactors` | `AccelMapGainCoolant`, `AccelTpsRateLimit`, `AccelTpsCoolantFactor`, члены по барометру, `AccelRpmFactor` | `AccelMapGain`, `AccelTpsFuel`, `AccelFactor` |
| Обеднение при сбросе газа | `DecelLeanControl` | `DecelLeanAirflow` (обороты x дроссель), множители по ОЖ, времени, оборотам, MAP и барометру | `DecelLeanFuel` ($07C2,Z) |
| Отсечка при торможении двигателем | `FuelCutControl` | `DecelCutMapThreshold`, `DecelCutDelay`, минимальные обороты по ОЖ; ограничения оборотов и скорости | флаги `$0770,Z`, `DecelCutRpmFactor` |
| Уменьшение топлива при сбросе | `DecelFuelRampControl` | `DecelMapRpmLimit` (MAP x обороты) | `DecelFuelFactor` ($077A,Z) |
| Обогащение при долгом WOT | `WotEnrichControl` | `WotTimeEnrichMax` | `WotTimeEnrich` ($07AA,Z) |
| Обогащение на ХХ | `IdleEnrichment` | время работы, этанол x температура воздуха при пуске, время стоянки | `IdleEnrichFactor` ($07DA,Z) |
| Обогащение горячего двигателя | `HotEngineEnrichCalc` | `HotEngineEnrich` | `$0811,Z` |
| Температура воздуха | `FuelCorrections` | `FuelAirTempCorr` с весами по оборотам и MAP | множитель топлива |
| Фильтры MAP и дросселя | `MapTpsFilters` | коэффициенты фильтров при росте и падении MAP и дросселя по ОЖ при пуске | `MapFilterCoef`, `TpsFilterCoef` |

**Flex fuel.** Программа поддерживает машины на смесевом топливе: `FlexSensorCheck` проверяет вход
датчика состава топлива (`FlexSensorRaw`, $0A8E,Z) и следит за уровнем топлива, чтобы заметить
заправку, а код обучения (`FlexLearn...`, около
`FlexLearnMain`) определяет долю этанола по коррекциям кислородных датчиков (`FlexEthanolLearned` $0197,Z,
0-170, и `FlexEthanol` $0198,Z). Доля этанола затем выбирает ряды в топливных таблицах и таблицах УОЗ
`Flex...` и в таблице прокрутки. Включается битом калибровки $032C.6; в 05293190AC (бензиновая
машина) flex-таблицы нейтральны.

## Мониторы неисправностей

Мониторы сообщают результат через две подпрограммы: `ReportFault` ($245CC) считает
неудачную проверку и ставит бит неисправности, `ReportPass` ($24160) считает удачную и снимает
его; обе получают в Y строку `FaultTable`. По `LDY #строка` перед этими вызовами видно, какой код
сообщает каждая подпрограмма (`tools/constants.py` добавляет его в описания констант, которые
подпрограмма читает):

| Подпрограмма | Коды | Проверка |
|---|---|---|
| `Reset` | P1602 | PCM не запрограммирован |
| `BusTimeoutCheck` | P1687, P1695 | нет сообщений по шине от щитка / BCM |
| `ChecksumCheck` | P0601 | контрольная сумма |
| `VacuumLeakMonitor` | P1299 | подсос воздуха (ожидаемый MAP по дросселю и оборотам) |
| `MapKeyOnCheck, MapCircuitCheck` | P0106, P0107, P0108 | MAP: правдоподобие, низкий, высокий |
| `O2ShortHighCheck` | P0132, P0152 | верхний O2 высокий, банки 1 и 2 |
| `PurgeSolenoidCheck` | P0443 | цепь клапана продувки |
| `EgrPositionMonitor, EgrSolenoidCheck` | P0405, P0406, P0403 | датчик положения EGR, низкий и высокий уровень; цепь клапана EGR |
| `WotLeanMonitor` | P1298 | бедно на WOT |
| `FlexFaultReport` | P1496 | низкое питание 5 В |

| `O2DownCircuitCheck` | P0137, P0138, P0157, P0158 | нижний O2, низкий и высокий уровень, банки 1 и 2 |

Мониторы пропусков зажигания, катализатора, датчиков O2, утечек EVAP и расхода продувки сообщают
через собственные автоматы состояний; их константы названы по монитору (`Misfire...`,
`CatMon...`, `O2Mon...`, `Ldp...`, `PurgeMon...`).

Проверка P0176 в `FlexSensorCheck` меняет одно прежнее прочтение: $0A8E,Z, считавшийся уровнем
топлива, — это вход датчика состава топлива (теперь `FlexSensorRaw`), а проверка P1697 показывает,
что слово $000D,Z — пробег SRI (напоминания о сервисе, `SriMileage`).

## Таблица неисправностей

`FaultTable` ($4052) — 256 строк по 10 байт:

| Байт | Содержимое |
|---|---|
| 0 | номер строки |
| 1 | счётчик срабатываний |
| 2 | блинк-код (BCD, как мигает лампа Check Engine) |
| 3 | биты атрибутов |
| 4, 5 | маска и смещение байта бита неисправности в массиве битов неисправностей |
| 6, 7 | P-код (BCD): $03 $40 = P0340 |
| 8, 9 | не используются (ноль) |

P-код есть в 83 строках; список — в каталоге. Есть коды цилиндров 5 и 6 (P0205, P0206, P0355),
так что программа рассчитана и на шестицилиндровые двигатели.

## Инструменты

```sh
python3 tools/caltables.py roms/05293190AC.bin        # список найденных таблиц
python3 tools/catalogue.py roms/05293190AC.bin docs/catalogue/05293190AC.md
```

`tools/caltables.py` находит подпрограммы выборки по байтам их кода, поэтому работает и на других
образах на 256 КБ: 397 таблиц в 05269833AH, 404 в 05269833AI и 05269834AJ, 462 в 05032017AA. У
семейств на 128 КБ код выборки другой, это тема этапа 5. Имена и единицы берутся из
`annotations/tables.json` и применяются только к эталону.

## Открытые вопросы

- Часть имён таблиц опирается только на то, как код использует значение (температура АКБ,
  скважность обмотки возбуждения генератора, датчик кондиционера, $019C,Z как вероятный уровень
  топлива; продувка адсорбера, EGR и круиз-контроль как подсистемы), а несколько переменных ОЗУ
  пока названы по адресу (`V0335`, `V006B`). Проверка на работающей машине это прояснит.
- У 1 036 переменных ОЗУ есть имена, включая массивы битов неисправностей FaultSet00-1B и
  FaultMem00-1B и байты состояния мониторов и стоп-кадра. Байты флагов, биты которых используют
  несколько подсистем, названы нейтрально. 768 других смещений от Z пока известны только по
  адресу; из них лишь 5 используются десять раз и больше, а 404 — один-два раза. В описаниях
  констант такие адреса указаны как $xxxx,Z.
- Семь выборок, где адрес таблицы берётся из указателя, а не из `LDX #` (например, по адресам
  $146E4 и $1974A), пока не прослежены.
